# ServerMineCities — правила проекта

## Область проекта

Этот репозиторий содержит только `ServerMineCities` (Градострой), его 16 внутренних Gradle-модулей, compile-only `Economy API` и клиентский ресурспак. Сервер устанавливает Cities одним JAR. `ServerMineEconomy` остаётся отдельным обязательным плагином.

## Среда

- Java 25, Gradle Kotlin DSL и включённый Wrapper.
- Purpur/Paper 26.2; для обычной серверной интеграции использовать Bukkit/Paper API.
- SQLite принадлежит только Cities; не читать и не изменять базу Economy.
- Не добавлять NMS/CraftBukkit без отдельного архитектурного решения.

## Архитектура и безопасность

- GUI — только представление. При изменениях повторно проверять участника, разрешение, revision, цену, стадию и доступность цели.
- Денежные операции проводить через Economy API и стабильный operation ID. Не повторять операцию с неизвестным результатом под новым ID.
- SQL не выполнять в горячих обработчиках Bukkit; изменения инвентарей и мира выполнять на главном потоке.
- Внутренние Cities-модули не публиковать как самостоятельные серверные плагины.
- Не включать Economy-классы в `ServerMineCities` JAR; зависимость объявлена в `plugin.yml`.
- Не использовать демонстрационные данные GUI как состояние реального города.

## Геймплей

- Стадии: SETTLEMENT → VILLAGE → CITY → CAPITAL → KINGDOM; лимиты 4/12/24/40/64.
- Город основывается с четырьмя чанками; поселение не может покупать пятый чанк.
- Claims должны быть связными и проверять системные зоны.
- Улучшения открывают возможности, но не дают прямой прибавки к лимиту чанков.
- Не добавлять телепортацию на городскую площадь.

## Рабочий процесс

1. Прочитать README и ROADMAP; выполнять одну законченную задачу на отдельной ветке.
2. Добавить/обновить тесты для доменного правила, миграции или транзакции.
3. Перед коммитом запустить `./gradlew clean build` и проверить итоговый diff.
4. Не коммитить `.gradle/`, `build/`, базы, ключи, серверные конфиги, логи и миры.
5. В PR описывать поведение, проверку и известные ограничения.
