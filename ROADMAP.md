# План разработки ServerMineCities

Этот план относится только к плагину городов **ServerMineCities / Градострой**. Economy имеет собственный репозиторий и жизненный цикл; здесь хранится только compile-only контракт API, нужный для интеграции.

## Уже реализовано

- [x] Java 25, Gradle Wrapper, сборка одного Cities JAR из 16 модулей и GitHub Actions.
- [x] Публичный Cities API, доменное ядро и versioned SQLite-схема.
- [x] Основание города 2×2 с проверкой чанков, мира, границы и системных зон.
- [x] Рост территории соседними чанками с ценой, лимитами стадии и проверкой разрешений.
- [x] Участники, приглашения, роли, выход/исключение и передача руководства.
- [x] Кэш владений и защита блоков, контейнеров, механизмов, огня, потоков и взрывов.
- [x] Городская казна, история операций, пополнение физическими монетами и межсервисная проверка операций.
- [x] Все стадии прогрессии и сохраняемые улучшения с ценами, требованиями и эффектами.
- [x] Дипломатические предложения и договоры с подтверждением, сроками и журналом.
- [x] Торговые договоры, объявления рынка, покупка из казны, комиссия и доставка товара.
- [x] Городские законы и настраиваемый ежедневный налог.
- [x] Рабочая книга управления: территория, жители, улучшения, управление, казна, дипломатия, законы, рынок и OP-инструменты.
- [x] Отдельный ресурсовый пакет с рамками, кнопками и динамическим текстом книги.
- [x] Модульные тесты, проверка упаковки JAR и CI-сборка.

## Ближайшие этапы

### 1. Надёжность платежей и восстановление

- [ ] Завершить автоматическое и административное разрешение операций с неизвестным результатом после сбоя.
- [ ] Добавить сценарии рестарта между каждой фазой `reserve → domain commit → economy commit/release`.
- [ ] Добавить конкурентные тесты для покупки чанка, налогов, переводов и рынка.
- [ ] Подготовить операторскую инструкцию по резервным копиям и сверке казны.

Готово, когда повтор после сбоя не создаёт двойную оплату или доменное изменение, а все неоднозначные операции можно безопасно сверить.

### 2. Защита территории и совместимость

- [ ] Проверить транспорт, вагонетки и другие способы перемещения блоков через границу чанка.
- [ ] Добавить отдельные адаптеры или документацию для совместимости с внешними региональными плагинами.
- [ ] Расширить тесты на границы claim, смену мира, отключение игрока и редкие события Bukkit/Paper.

Готово, когда действия игроков и игровых механизмов не обходят правила города и интеграция не зависит от внутренностей сторонних плагинов.

### 3. Проверка GUI в игре

- [ ] Проверить книгу с включённым и выключенным ресурспаком на целевой версии клиента.
- [ ] Проверить GUI Scale, разрешения экрана и длинные названия городов/игроков.
- [ ] Проверить все кнопки, возврат, подтверждения, повторные клики и закрытие меню во время операции.
- [ ] Добавить актуальные игровые снимки экранов в документацию после проверки на сервере.

Готово, когда интерфейс читаем на обычных настройках клиента, а без ресурспака все действия остаются понятными.

### 4. Выпуск и сопровождение

- [ ] Зафиксировать публичную совместимость API и правила версионирования.
- [ ] Автоматизировать выпуск JAR и ресурспака с номером версии и заметками об изменениях.
- [ ] Добавить инструкцию обновления схемы SQLite и восстановления резервной копии.
- [ ] Провести нагрузочное тестирование рынка, защиты и фоновых задач на тестовом сервере.

Готово, когда релиз воспроизводим, обновление не теряет данные и администратор может безопасно откатиться.

## Продуктовые ограничения

- Город начинает с четырёх чанков; лимиты стадий — 4/12/24/40/64.
- Поселение должно перейти в Деревню до покупки пятого чанка.
- Улучшения не увеличивают лимит территории напрямую.
- Телепортация на городскую площадь не планируется.
- GUI показывает данные сервисов; визуальные предметы и ресурспак не являются источником состояния.
