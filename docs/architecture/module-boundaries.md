# Границы модулей

| Модуль | Владелец данных / назначение | Текущее состояние |
|---|---|---|
| economy-api | Compile-only контракты физических денежных операций | Включён в исходный репозиторий для сборки; runtime реализуется отдельным ServerMineEconomy |
| cities-api | Неизменяемые CityView, ChunkPosition, CityStage, CitiesService и контракты основания | Реализован начальный API |
| cities-core | Контракт репозитория и read-only CitiesService; публикация опционального founding API | Реализован |
| cities-creation | Нормализация и оркестрация идемпотентного основания | API подключён к мастеру книги |
| cities-protection | Проверка загруженного мира, border и системных запретных зон | Реализовано для основания; дипломатические союзы и пакты применяются к PvP |
| cities-storage | SQLite schema v8, миграции, операции городов, состав, роли, claims, upgrades, дипломатия, рынок, казны и журналы | Транзакционные изменения, права, upgrades, договоры, переводы казны, торговые расчёты и аудит тестовых админ-изменений реализованы |
| cities-territory | Владение, соседство, caps и покупка из казны | Реализовано через Cities write service |
| cities-members | Состав города и приглашения | Выход, приглашение, вступление и исключение реализованы |
| cities-roles | Назначение ролей и централизованная политика прав | Подключённый сервис; назначения проверяются и журналируются в storage |
| cities-treasury | Городская казна и интеграция с Economy | Пополнение, история, recovery, атомарные расходы и межгородские переводы по торговому договору реализованы |
| cities-progression | Последовательность этапов | Все переходы SETTLEMENT → VILLAGE → CITY → CAPITAL → KINGDOM с требованиями и оплатой из казны |
| cities-upgrades | Улучшения, зависимости и эффекты | Два сохраняемых улучшения защиты подключены; дерево расширяемо |
| cities-market | Межгородские объявления и покупки | Объявления, сборы, торговые договоры и постоянные доставки подключены к SQLite |
| cities-diplomacy | Межгородские отношения | Союзы, пакты о ненападении и торговля имеют эффекты в PvP и переводах казны |
| cities-gui | Книга, отрисовка, сессии, навигация и мастер основания | Подключены жители, территория, этапы, казна, дипломатия и рынок |
| cities-admin | Административные команды | status, givebook, preview и команды казны/состава/территории |
| cities-plugin | Композиция, конфигурация, ServicesManager и lifecycle I/O executor | Один серверный JAR; проверка DB-схемы идёт до регистрации сервиса |

Каждая реализация зависит от своего API/core. Admin использует публичные адаптеры GUI для выдачи книги и предпросмотра.
Feature-модули не читают репозитории соседей. Экономические зависимости Cities — только compileOnly на economy-api.
Казна Cities никогда не размещается в БД Economy.

Структуру зависимостей можно получить `./gradlew projects` и `./gradlew :cities:cities-plugin:dependencies`.
Группирующие Gradle-проекты `cities` и `economy` не являются библиотеками/плагинами.

Интерфейсы репозитория принадлежат core; SQLite-реализация — storage; создание и инъекция выполняются в cities-plugin.
Не добавлять Bukkit в публичный Cities API. Protection должен оставаться заменяемым адаптером для будущего выделения в отдельный плагин.
